# JUDO End-to-End Testing

This skill provides reference documentation for writing end-to-end (e2e) tests for JUDO applications. E2e tests verify the full application stack -- from the React frontend through the REST API to the backend and database -- ensuring that the generated and customized application works correctly from the user's perspective.

## Overview

JUDO e2e tests use **Playwright** as the browser automation framework. The testing approach is designed around the generated UI structure, providing:

- **Page object patterns** tailored to JUDO's generated component structure
- **Reliable selectors** using data-testid attributes generated by the JUDO frontend
- **Test scenarios** covering common CRUD workflows, navigation, and custom operations
- **CI integration** for running tests in headless mode as part of the build pipeline

## Architecture

```
Playwright Test
  └── Page Objects (custom layer)
       └── Generated UI (React + MUI)
            └── JUDO REST API
                 └── Backend (custom operations + DAO)
                      └── Database
```

E2e tests are the most comprehensive but also the slowest tests. They should focus on critical user flows and integration points that cannot be covered by unit or integration tests alone.

## What to Test with E2e

- Complete user workflows (create, edit, view, delete)
- Navigation between pages and breadcrumb behavior
- Custom component overrides and their integration
- Authentication flows (login, session management, role-based access)
- Error handling as displayed to the user
- Data grid behavior (filtering, sorting, pagination)

## What Not to Test with E2e

- Individual backend operations (use integration tests)
- Component styling details (use visual regression tools)
- Edge cases that can be covered with unit tests
