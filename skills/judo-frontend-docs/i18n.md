# Internationalization (i18n)

## Overview

The frontend uses **react-i18next** for internationalization. Translation files are located in the `public/i18n/` directory and support multiple languages.

## Directory Structure

**IMPORTANT**: JUDO generates translation files in a flat structure, NOT in subdirectories.

```
public/i18n/
├── application_default.json   # Generated application translations (fallback)
├── application_en-US.json     # Generated application translations (English)
├── application_hu-HU.json     # Generated application translations (Hungarian)
├── system_default.json        # JUDO system translations (fallback)
├── system_en-US.json          # JUDO system translations (English)
└── system_hu-HU.json          # JUDO system translations (Hungarian)
```

**Key Points**:
- ❌ **NOT** organized in subdirectories like `en-US/translation.json`
- ✅ **YES** flat structure with `{type}_{locale}.json` naming
- **application_*.json** - Generated from your model (entities, enumerations, menu, services)
- **system_*.json** - JUDO platform UI translations (buttons, modals, table controls)
- **_default.json** files serve as fallback when specific locale not found

## Translation File Format

### Structure

**JUDO uses flat dot-notation keys**, not nested objects:

```json
{
  "translation": {
    "entities.Entity.Entity_View_Edit.title": "Title",
    "entities.Entity.Entity_View_Edit.fromDate": "From Date",
    "entities.Entity.Entity_View_Edit.toDate": "To Date",
    "enumerations.StatusType.DRAFT": "Draft",
    "enumerations.StatusType.ACTIVE": "Active",
    "enumerations.StatusType._null": "None",
    "menuTree.Entities": "Entities",
    "menuTree.Items": "Items",
    "services.entity_service.Entity.Entity_Form.title": "Title"
  }
}
```

### Key Naming Conventions

JUDO generates translation keys following these patterns:

| Pattern | Example | Purpose |
|---------|---------|---------|
| `entities.[Entity].[Component].[field]` | `entities.User.User_View_Edit.firstName` | Entity field labels |
| `enumerations.[EnumType].[VALUE]` | `enumerations.StatusType.ACTIVE` | Enumeration values |
| `enumerations.[EnumType]._null` | `enumerations.StatusType._null` | Null/empty enum value |
| `menuTree.[MenuLabel]` | `menuTree.Master data` | Navigation menu items |
| `services.[service].[Entity].[Component].[field]` | `services.user_service.User.User_Form.email` | Service-specific labels |
| `faults.northwind.[path].[Fault].[field]` | `faults.myapp.entities.BusinessError.message` | Custom fault messages |
| `extra.localization.operation.[operationName]` | `extra.localization.operation.createUser` | Custom operation labels |

## Using Translations in Code

### Basic Usage

```typescript
import { useTranslation } from 'react-i18next';

export const EntityList = () => {
  const { t } = useTranslation();
  
  return (
    <div>
      <h1>{t('entities.title')}</h1>
      <button>{t('entities.create')}</button>
    </div>
  );
};
```

### With Parameters

```typescript
import { useTranslation } from 'react-i18next';

export const ValidationMessage = ({ min, max }) => {
  const { t } = useTranslation();
  
  return (
    <div>
      <p>{t('validation.minLength', { min })}</p>
      <p>{t('validation.maxLength', { max })}</p>
    </div>
  );
};

// Renders:
// "Minimum length is 5 characters"
// "Maximum length is 100 characters"
```

### Pluralization

**Translation file:**
```json
{
  "items": {
    "count_one": " item",
    "count_other": " items"
  }
}
```

**Usage:**
```typescript
const { t } = useTranslation();

console.log(t('items.count', { count: 1 }));  // "1 item"
console.log(t('items.count', { count: 5 }));  // "5 items"
```

### Nested Translation Keys

```typescript
const { t } = useTranslation();

// Access nested keys
t('entities.fields.title')        // "Title"
t('entities.status.active')       // "Active"
t('validation.required')          // "This field is required"
```

## Language Switching

### Get Current Language

```typescript
import { useTranslation } from 'react-i18next';

export const LanguageInfo = () => {
  const { i18n } = useTranslation();
  
  return (
    <div>
      Current language: {i18n.language}
    </div>
  );
};
```

### Change Language

```typescript
import { useTranslation } from 'react-i18next';
import { Button } from '@mui/material';

export const LanguageSelector = () => {
  const { i18n } = useTranslation();
  
  const changeLanguage = (lang: string) => {
    i18n.changeLanguage(lang);
  };
  
  return (
    <div>
      <Button onClick={() => changeLanguage('en-US')}>English</Button>
      <Button onClick={() => changeLanguage('hu-HU')}>Magyar</Button>
    </div>
  );
};
```

### Language Dropdown

```typescript
import { useTranslation } from 'react-i18next';
import { Select, MenuItem } from '@mui/material';

export const LanguageDropdown = () => {
  const { i18n } = useTranslation();
  
  const handleChange = (event) => {
    i18n.changeLanguage(event.target.value);
  };
  
  return (
    <Select value={i18n.language} onChange={handleChange}>
      <MenuItem value="en-US">English (US)</MenuItem>
      <MenuItem value="hu-HU">Magyar</MenuItem>
    </Select>
  );
};
```

### Register in AppBar

```typescript
// src/custom/application-customizer.tsx
import { LanguageDropdown } from './components/LanguageDropdown';

export const applicationCustomizer: ApplicationCustomizer = {
  appBarComponents: [LanguageDropdown],
};
```

## Custom Translation Provider

### Load Translations from Backend (Advanced)

**IMPORTANT**: JUDO loads translations from `public/i18n/` files by default. You typically don't need a custom provider.

If you need dynamic translations from your backend:

```typescript
// src/custom/l10n/translationProvider.tsx
import { L10NTranslationProvider, L10NTranslations } from '~/generated';
import { translationServiceImpl } from '~/services/data-axios/TranslationServiceImpl';

export class ApiTranslationProvider implements L10NTranslationProvider {
  async provideTranslations(locale: string): Promise<L10NTranslations> {
    // ✅ CORRECT: Use generated service if your backend has translation operations
    // Note: This requires you to model a translation service in your ESM
    try {
      const response = await translationServiceImpl.getTranslations(locale);
      
      return {
        systemTranslations: response.data.system || {},
        applicationTranslations: response.data.application || {}
      };
    } catch (error) {
      console.error('Failed to load translations:', error);
      // Fallback to empty translations
      return {
        systemTranslations: {},
        applicationTranslations: {}
      };
    }
  }
}

// Register in application-customizer.tsx
import { L10N_TRANSLATION_PROVIDER_INTERFACE_KEY } from '~/generated';

context.registerService<L10NTranslationProvider>(
  L10N_TRANSLATION_PROVIDER_INTERFACE_KEY,
  new ApiTranslationProvider()
);
```

**Note**: For most use cases, simply edit the `public/i18n/application_{locale}.json` files directly. Custom providers are only needed for dynamic translations loaded from a database.

## Date and Time Formatting

### Using date-fns with i18n

```typescript
import { useTranslation } from 'react-i18next';
import { format } from 'date-fns';
import { enUS, hu } from 'date-fns/locale';

export const FormattedDate = ({ date }: { date: Date }) => {
  const { i18n } = useTranslation();
  
  const locale = i18n.language === 'hu-HU' ? hu : enUS;
  
  return (
    <span>
      {format(date, 'PPP', { locale })}
    </span>
  );
};

// en-US: "December 25, 2024"
// hu-HU: "2024. december 25."
```

### Number Formatting

```typescript
import { useTranslation } from 'react-i18next';

export const FormattedNumber = ({ value }: { value: number }) => {
  const { i18n } = useTranslation();
  
  const formatter = new Intl.NumberFormat(i18n.language, {
    style: 'decimal',
    minimumFractionDigits: 2,
    maximumFractionDigits: 2,
  });
  
  return <span>{formatter.format(value)}</span>;
};

// en-US: "1,234.56"
// hu-HU: "1 234,56"
```

### Currency Formatting

```typescript
export const FormattedCurrency = ({ value }: { value: number }) => {
  const { i18n } = useTranslation();
  
  const formatter = new Intl.NumberFormat(i18n.language, {
    style: 'currency',
    currency: i18n.language === 'hu-HU' ? 'HUF' : 'USD',
  });
  
  return <span>{formatter.format(value)}</span>;
};

// en-US: "$1,234.56"
// hu-HU: "1 235 Ft"
```

## Translation Management

### Finding Missing Translations

```bash
# Create a script to compare translation files
cd public/i18n

# List all keys in default (English)
jq -r '.translation | keys[]' application_default.json | sort > default-keys.txt

# List all keys in Hungarian
jq -r '.translation | keys[]' application_hu-HU.json | sort > hu-keys.txt

# Find missing keys in Hungarian
comm -23 default-keys.txt hu-keys.txt

# Find extra keys in Hungarian (not in default)
comm -13 default-keys.txt hu-keys.txt
```

### Translation File Validation

```typescript
// scripts/validate-translations.ts
import appDefault from '../public/i18n/application_default.json';
import appHuHU from '../public/i18n/application_hu-HU.json';

// Keys are flat in the translation object
const defaultKeys = Object.keys(appDefault.translation);
const huKeys = Object.keys(appHuHU.translation);

const missingInHu = defaultKeys.filter(k => !huKeys.includes(k));
const extraInHu = huKeys.filter(k => !defaultKeys.includes(k));

console.log('Missing in Hungarian:', missingInHu);
console.log('Extra in Hungarian (not in default):', extraInHu);

// Check for empty translations
const emptyInHu = huKeys.filter(k => {
  const value = appHuHU.translation[k];
  return !value || value.trim() === '';
});

console.log('Empty translations in Hungarian:', emptyInHu);
```

## Best Practices

1. **Don't Edit Generated Files** - `application_*.json` files are regenerated
   ```bash
   # These are GENERATED - changes will be lost:
   public/i18n/application_default.json
   public/i18n/application_en-US.json
   
   # Safe to edit for localization:
   public/i18n/application_hu-HU.json
   public/i18n/application_de-DE.json
   ```

2. **Use Flat Dot-Notation Keys** - JUDO generates flat structure
   ```json
   {
     "translation": {
       "entities.User.User_Form.firstName": "First Name"
     }
   }
   ```

3. **Follow JUDO Key Conventions** - Match generated patterns
   ```json
   {
     "entities.Entity.Component.field": "Label",
     "enumerations.EnumType.VALUE": "Display Value",
     "menuTree.Menu Item": "Menu Item"
   }
   ```

4. **Keep Translations Synced** - Maintain all language files
   ```bash
   # Check for missing translations regularly
   cd public/i18n
   diff <(jq -r '.translation | keys[]' application_default.json | sort) \
        <(jq -r '.translation | keys[]' application_hu-HU.json | sort)
   ```

5. **Use Parameters** - For dynamic content (works same as before)
   ```typescript
   t('messages.welcome', { name: 'John' })
   // "Welcome, John!"
   ```

6. **Test All Languages** - Switch between languages during testing
   ```typescript
   i18n.changeLanguage('hu-HU');
   // Test functionality
   ```

7. **Maintain Default Fallback** - Always have `application_default.json`
   ```
   public/i18n/application_default.json  ← Fallback
   public/i18n/system_default.json       ← Fallback for system strings
   ```

8. **Translate Enumerations** - Don't forget `_null` values
   ```json
   {
     "enumerations.StatusType.ACTIVE": "Aktív",
     "enumerations.StatusType.DRAFT": "Vázlat",
     "enumerations.StatusType._null": "Nincs megadva"
   }
   ```

## Troubleshooting

### "Translation key not found"

**Check key path:**
```typescript
// Correct - use full dot-notation path
t('entities.User.User_View_Edit.firstName')

// Wrong
t('User.firstName')              // Missing prefix
t('entities.User.firstName')     // Missing component name
```

**Verify key exists:**
```bash
# Check if key exists in translation file
cat public/i18n/application_default.json | jq '.translation["entities.User.User_View_Edit.firstName"]'

# List all keys matching pattern
cat public/i18n/application_default.json | jq -r '.translation | keys[] | select(contains("User"))'
```

### "Language not changing"

**Clear i18n cache:**
```typescript
i18n.changeLanguage('hu-HU');
window.location.reload();  // Force reload
```

**Check language code:**
```typescript
// Correct
i18n.changeLanguage('en-US')

// Wrong
i18n.changeLanguage('en')     // Missing region
i18n.changeLanguage('en-us')  // Wrong case
```

### "Translations not loading"

**Verify file location:**
```bash
ls -la public/i18n/application_default.json
ls -la public/i18n/application_hu-HU.json
# Should exist
```

**Check JSON syntax:**
```bash
cat public/i18n/application_default.json | jq .
# Should output formatted JSON with "translation" key at root
```

**Verify structure:**
```bash
# Should have "translation" key at root
cat public/i18n/application_default.json | jq 'keys'
# Output: ["translation"]

# Should have flat keys inside translation
cat public/i18n/application_default.json | jq '.translation | keys[0:5]'
# Output: ["entities.User...", "enumerations.Status...", ...]
```
